Git knows who committed it. Not who wrote it.

You, Claude Code and Codex all edited the same file, and git blame puts your name on every line. proveGIT records which human, agent and model wrote each character, as it's written, on your machine.

npm install -g provegit

An agent writes two hundred lines. You fix a constant. A second agent refactors the result, and you commit. Git stores one author for all of it: whoever ran git commit.

  • Which of these lines has a person actually read?

    Reviewers treat a 600-line pull request the same whether you typed it or an agent produced it in one pass. They have no way to tell where to look harder.

  • Which model wrote the bug?

    When something breaks in production, the commit points at you. The session, model and effort level that produced the line are gone.

  • How much of this is machine-generated?

    Copyright reviews and disclosure rules for AI-generated content, such as Article 50 of the EU AI Act, start with a question your repository can't answer.

It can't be reconstructed later. Agents compact their context, sessions get deleted, and a squash merge flattens what's left. If an edit isn't recorded when it happens, nobody can say afterwards who wrote it.

Record every edit as it happens

proveGIT hooks into your coding agents and watches your working tree. Each edit is stored with its author before a commit can flatten it.

  1. Install it in a repository

    prov init marks the existing code as yours and installs hooks for Claude Code, Codex and OpenCode. It takes a few seconds.

    $ npm install -g provegit$ prov init --hooksprov init: baseline 214 files → h:you

  2. Work the way you already do

    When an agent edits a file, the hook records the patch along with the agent, model, effort level and session. prov watch picks up what you type yourself.

    $ prov watch+ src/checkout.ts → h:you~ src/checkout.ts → agent:claude/claude-fable-5@high (hook)~ src/checkout.ts → agent:codex/gpt-5@medium (hook)~ src/checkout.ts → h:you

  3. Ask who wrote it

    prov blame answers for a file, prov stats for the whole repository, and prov ui opens a diff viewer where every character is tinted by its author.

    $ prov statsrepo provenance h:you 31% 187 files agent:claude/claude-fable-5@high 44% 96 files agent:codex/gpt-5@medium 19% 41 files agent:opencode/claude-sonnet-5-5 6% 12 files

Built to be believed

An authorship record is only useful if it's precise, hard to fake and still there after the history is rewritten.

Characters, not lines
Change one constant inside an agent's line and only the characters you typed become yours. The rest of the line stays with the agent.
The last editor owns it
One rule decides every case: whoever last touched a character wrote it. prov claim corrects the record when an edit was attributed to the wrong author.
Every agent in one record
Claude Code, Codex and OpenCode report through their own hooks, subagents included. Tools without hooks are caught by the file watcher.
Nothing leaves your machine
The record is a SQLite file in your repository. proveGIT never calls a model API and makes no network requests until you run prov sync.
Survives rebase and squash
Provenance is stored against file content, not commits, so rewriting history doesn't change who wrote what.
Tampering is detectable
When you sync, the server replays every patch and checks the result against a SHA-256 of the file. An edited history is rejected.

Questions

Why can't git blame tell me which code was written by AI?

Git stores one author per commit, and that author is whoever ran git commit. Edits made by a coding agent in your working tree look identical to edits you typed. proveGIT records each edit at the moment it happens, so the author is known before the commit flattens it.

Does proveGIT send my code anywhere?

No. Recording, blame, stats and the diff viewer all run on your machine against a SQLite file in your repository. proveGIT never calls a model API. Patches leave your machine only if you run prov sync against a server you choose.

Which coding agents does proveGIT support?

Claude Code, Codex and OpenCode are recorded through their hook systems, including the model and effort level of each session. Tools without hooks are picked up by the file watcher, which records the edit but may not know the model.

What happens when I edit code an agent wrote?

The characters you touch become yours and the rest of the line stays with the agent. Ownership always belongs to the last editor. If an edit was attributed to the wrong author, prov claim corrects it.

Does provenance survive a rebase or squash merge?

Yes. Provenance is stored against file content, not commits, so rewriting history does not change who wrote which characters.

Can I add proveGIT to a repository that already has code in it?

Yes. prov init attributes the existing code to you as a baseline and records every edit from then on. Edits made before you installed it cannot be recovered, which is the reason to start recording early.
